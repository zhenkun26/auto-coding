# Set Up Auto-Coding

Inspect existing instructions, project commands, plan/status conventions, and
knowledge records. Reuse what already answers the workflow; do not duplicate a
configuration just because setup was requested.

When useful, add a short `## auto-coding` section to the applicable repository
instructions pointing to the plan/status authority, important protected behavior,
acceptance commands, and knowledge records that are not otherwise discoverable.
Only record meaningful deviations from the defaults. Ask about consequential
unknown preferences, not facts found in the repository.

Preserve existing instructions and authority. A setup request authorizes the
necessary local guidance edit; broader configuration, dependencies, or external
actions still need their corresponding authority. Report the actual diff and how
it affects future work. Do not initialize a specification system or task-state
file as part of setup unless requested.

## Existing profiles

Honor established strict/default/light preferences as review-depth preferences,
not file-count gates or changes to acceptance and permissions. All profiles keep
meaningful risk controls and complete the agreed outcome. No profile interview
or replacement format is required; use the repository's language and conventions.
