# auto-coding 记忆策略：运行过程中的遗忘应对

> 本文档定义 skill 在长任务与跨会话执行中对抗"记忆遗忘"的设计模型与操作规则。
> 决策记录见 [DECISIONS.md](DECISIONS.md) ADR-AC-006；操作细则见
> `references/recovery.md`（断点状态）与 `references/sedimentation.md`（沉淀记忆）。

## 设计前提

**假设每一次轮次之间都会失忆。** 技能必须在"任何时刻杀掉会话"的条件下，仅凭仓库内的文件，把下一个执行实例恢复到同等的执行状态。聊天记录、模型上下文、上一次会话的输出，永远不作为权威记忆。

这个前提来自两类真实事故：长任务中会话被压缩或中断，模型凭"印象"继续干活，把上一会话的推断当成已验证的事实；以及跨会话接手时，新实例读不到旧实例的计划与证据，静默重做或静默遗漏。

## 四层记忆模型

| 层 | 载体 | 写入时机 | 生命周期 |
|:---|:---|:---|:---|
| L0 仓库即记忆 | git status / diff / log、测试与 CI 配置、`AGENTS.md`、`ERROR_MEMORY.md` | 天然存在，读取成本为零 | 永久 |
| L1 沉淀记忆 | `ai_pipeline/ERROR_MEMORY.md` | 自愈、逃逸门、Critical 失败发生时**立即**追加 | 永久，带压缩上限 |
| L2 断点状态 | `ai_pipeline/state.json`（单文件，原子写入） | 每个原子步骤完成后写入；仅长任务使用 | 任务级，完成即标记、确认后清除 |
| L3 交接报告 | 交付时的结构化输出（用户要求时可落盘） | 每次交付 | 一次性 |

分工原则：

- **L0 是默认记忆**。改动本身（diff）、测试与 CI、仓库指令就是绝大多数任务需要的全部状态——这正是"默认不产生过程文件"成立的原因。任何一层启用前，先确认 L0 不够用。
- **L1 是跨任务学习**。它记录的不是"做了什么"，而是"下次怎么不再犯"：错误 → 修复 → 预防规则。任务开始时先读它。
- **L2 是任务内断点**。只保存恢复执行所需的最小字段（路由、阶段、当前任务、自愈轮次、续跑提示），由 `scripts/manage_state.py` 原子化读写，崩溃不会留下半截文件。
- **L3 是对人的记忆**。交接报告按"改动 + 证据 + 假设与风险 + 待授权动作"四段组织，使得用户把它粘贴进一个全新会话即可引导下一个实例接手。

## 反遗忘五规则

1. **文件优先于聊天**。重要结论若不在文件里，就视为不存在。宁可多写一行断点到 state 文件，不要相信"我记得"。
2. **证据有时效**。恢复会话后，上一会话的一切 `PASS` 一律视为**未验证**；按当前路由要求重跑关键闸门之后才能在其上继续。旧命令输出是上下文，不是证据。这是整套策略里最核心的反幻觉规则——遗忘的不只是计划，还有旧证据的可信度。
3. **单一状态源**。一个任务至多一个 state 文件；发现多个状态来源（state 文件、遗留 STATUS 树、聊天里的计划）相互矛盾时，停止实现并报告，以仓库现实为最终事实。
4. **恢复优先于重做，重做优于带陈旧计划继续**。断点与工作区、治理计划仍然一致 → resume；计划与仓库现实冲突、diff 无法辨认、过半任务无法定位 → restart，并如实说明原因。
5. **沉淀有上限**。`ERROR_MEMORY.md` 是规则库不是日志堆：条目超过约 100 条时触发合并提炼——重复模式升格为预防规则，已解决的问题裁撤。压缩本身是一个被报告的动作，不做静默重写。

## 恢复协议（操作层）

```text
新实例进入任务
  → 读 AGENTS.md 与仓库指令（L0）
  → 发现 ai_pipeline/ERROR_MEMORY.md → 先读（L1）
  → 发现 ai_pipeline/state.json 非空
      → 打印断点：phase / current_task / current_file / self_heal_round
      → 询问：resume（从断点继续）或 restart（重新开始）
      → resume 时：旧证据全部标记未验证，按路由重跑关键闸门（规则 2）
  → 无 state 文件 → 按正常工作流开始，长任务在建状态文件前先声明理由
```

## 与规格系统解耦后的分工

v1 中 OpenSpec 的 change 目录承担了一部分"计划状态"的职责。v2 将规格系统降级为可选外挂后，计划状态的默认落点是 L2（state.json）与 L3（交接报告）；选用 OpenSpec 的仓库由伴侣 skill 恢复其 change 目录作为规划权威。四层模型不依赖任何特定规格系统，因此这次解耦不削弱记忆能力。
