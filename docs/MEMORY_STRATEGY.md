# auto-coding 记忆策略

本设计由 ADR-AC-010 更新 ADR-AC-006 的历史方案。目标是中断后能找回目标、授权、剩余工作和证据，而不是复制聊天或每次从头检查。

## 一个当前权威，三类信息

| 信息 | 默认载体 | 写入条件 |
|:---|:---|:---|
| 项目知识 | 已有决策记录、领域说明、仓库指令 | 已验证、非显然、能避免再次犯错或大量重复调查的结论 |
| 当前任务状态 | 已有 STATUS／当前 STEP／工作计划 | 阶段变化、重要决策、阻塞、交接或完成时；长任务在关键节点更新 |
| 验证证据 | 已有检查报告／CI／必要的本地输出 | 实际运行后，记录命令、退出码、受检内容、工具环境和适用范围 |

这是信息分工，不是三份必填文档。小任务可由 diff、检查输出和交付说明完整表达；已有 STATUS 和 STEP 的项目继续使用它们。只有独立长任务确实没有状态权威时，才使用一个可选 JSON 记录。不得同时维护两套相互竞争的完成状态。

稳定事实以实际代码和工具证据为准；目标和授权以用户要求及适用项目约定为准。代码现状不能擅自改变目标，聊天里的“已完成”也不能覆盖实际失败。

## 最小恢复内容

记录目标与不做什么、允许的动作及限制、治理计划指针、完成／剩余／阻塞、相关证据位置和精确下一步。保留仍然有效的授权，不因换会话反复确认；也不能把旧任务的授权迁移到新范围。

工具提供 `objective`、`boundary`、`plan_ref`、`completed`、`remaining`、`blockers`、`evidence`、`resume_hint`，并兼容旧路由和阶段字段。证据字符串应指向可复查记录；工具不会读取链接或代替语义验收。

## 恢复流程

1. 读适用指令和当前任务权威，确认尚未完成的授权目标。
2. 检查实际工作树、已有改动和可能未恢复的诊断实验。
3. 将证据对应到受检内容，包括未提交／新文件、命令、依赖和环境。
4. 保留未变且可追溯证据；重跑受影响或身份无法确认的检查。会话压缩本身不是全部重跑的理由。
5. 对可解释的状态差异更新记录；无法辨明的实质冲突仅阻塞相关工作。继续独立授权工作，不覆盖他人改动，不静默重启整个项目。
6. 按下一步继续，完成时将结果和限制写回同一个权威。

## 保留与沉淀

`init` 拒绝覆盖现有文件，完成记录使用 `complete --summary` 保留。旧 `clear` 是弃用别名，不能清空记录。新任务选择新路径；旧字段可以逐步补充，不做自动清理。失败的原子写入保留临时恢复文件，既有记录仍可用。

单写者工具不提供锁或跨进程仲裁，也不是审计级事件日志。外部／忽略路径里的证据不会自动进 Git；交付时明确保留位置。记录长期规则前先判断是否应以测试、lint 或 CI 修复机械性错误，避免提示词无限增长。

不强制创建 ERROR_MEMORY，不把每次调试过程永久沉淀。旧经验被新事实取代时记录替代关系，按项目规则整理，不无声删除。全局个人记忆仍需明确用户授权，本工作流不会自动修改宿主记忆。

操作细则见 [恢复](../references/recovery.md)、[选择性沉淀](../references/sedimentation.md)和[完成审查](../references/completion.md)。
