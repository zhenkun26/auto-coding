# auto-coding 精选问题复盘

> 仅记录验收报告、CHANGELOG 和测试中有直接证据的问题。v0.1.0 容器化路径已在 v0.2.0 移除；相关条目保留历史版本范围，不描述为当前部署能力。

## PR-AC-001：契约检查器静默吞错导致假性通过

- **真实现象与影响**：旧 `_contract_check.py` 对读取/解析异常使用宽泛 `except ...: continue`，损坏或不可读文件可能被跳过，契约检查错误地通过。
- **复现条件**：给检查器输入读取失败、非 UTF-8、语法错误或无效 source/spec 路径。
- **调查过程**：验收审查逐文件扫描异常路径；确认异常既没有诊断输出，也没有让 CLI 失败；同时确认参数缺失会触发 `sys.argv.index(...)+1` 越界。
- **失败方案**：继续用宽泛 catch 并把异常当“无契约”；把不存在的 source 当空目录。
- **最终根因**：错误处理把“无法检查”错误地等价为“没有问题”。
- **最终修复**：精确捕获并记录诊断；显式解析 CLI 参数；缺失 spec/source 快速失败；读取路径处理编码错误。
- **验证结果**：验收报告记录 36 个测试、契约边界、对抗性 fixtures 和 1000 次并发 CLI 冒烟；当前版本以 CHANGELOG 0.2.1 的测试扩展为准。
- **防止复发**：对异常输入建立陷阱 fixture；CI 必须执行契约、链接和插件同步检查。
- **个人反思**：验证工具本身也是生产关键路径，“没有发现问题”必须先证明“检查确实执行了”。

## PR-AC-002：验证声明与实际可验证边界混淆

- **真实现象与影响**：项目同时包含机器可验证的 CLI/脚本行为和依赖 agent 自律的 prompt 路由规则；若统一写成“已验证”，会夸大交付可信度。
- **复现条件**：阅读 v0.1.0 验收报告中 Docker/K8s 或 prompt 级规则的结论时，把历史容器验证和当前 v0.2.0 代码混用。
- **调查过程**：对比 CHANGELOG 0.2.0 的移除清单、验收报告的历史版本声明和 2026-08-07 的验证边界补充。
- **失败方案**：继续沿用“金融级审查”标题覆盖所有机制；把没有客观度量的 agent 行为规则当成自动化测试结果。
- **最终根因**：报告没有在每项结论上标注版本范围和证据类型。
- **最终修复**：明确机器验证层与执行者自律层；采用 PASS/FAIL/BLOCKED/NOT_APPLICABLE；README 标注不自动安装、提交、部署和无法执行的验证。
- **验证结果**：验收报告第 6 节记录 36 tests、对抗 fixture 和当前不可客观证明的 prompt 规则；CHANGELOG 0.2.0 记录容器与 pipeline 移除。
- **防止复发**：每份报告写明版本、证据类型和验证边界；历史报告不得覆盖当前目录事实。
- **个人反思**：诚实标注不可验证范围，比堆叠“生产级”形容词更能降低交付误判。
